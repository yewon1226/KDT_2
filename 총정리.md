### 4) READ TABLE vs Table Expression (`itab[ ]`)
- **`READ TABLE`** : 안전하게 조회하며, 대상이 없으면 `sy-subrc` 로 확인 가능(덤프 없음).
- **`itab[ ]`** : 코드가 간결하지만, 대상이 없으면 예외(덤프) 발생하며 `sy-subrc` 는 변경되지 않음.
```abap
CLASS zcl_a06_w01 IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
    SELECT carrid, carrname, currcode, 'Kang' AS testField FROM scarr
        INTO TABLE @DATA(airlines)
        WHERE currcode = 'USD'.

*    READ TABLE airlines INDEX 2 INTO DATA(airline).
    DATA(airline) = airlines[ 10 ].
    IF sy-subrc <> 0.
      out->write( 'Test' ).
    ENDIF.
    out->write( airline ).
  ENDMETHOD.
ENDCLASS.
```

```abap
ENDTRY.
```

```abap
      CATCH cx_dynamic_check INTO DATA(lo_ex).
```

### 8) VALUE 연산자와 필드 심볼 활용
#### Case 1 — 구조체 생성
- VALUE는 구조체를 그대로 넣을 수 없으며, 필드명 = 값 형식으로 필드를 지정해야 함
```abap
*   Case 1
    DATA ls_info LIKE connection.
    ls_info = value #( airpfrom = connection-airpfrom ).    " O (필드 지정)
*   DATA(ls_info) = value #( connection ).                  " X (구조체 전체 입력 → 오류)
```
</br>

#### Case 2 — 내부 테이블 생성
- 인터널 테이블을 `VALUE` 로 생성하려면 테이블 타입에 키(`WITH EMPTY KEY` 또는 `WITH KEY`)를 정의해야 함
```abap
 TYPES: BEGIN OF ts_info,
             carrid TYPE spfli-carrid,
           END OF ts_info,
           tt_info TYPE TABLE OF ts_info WITH EMPTY KEY.

*    MOVE-CORRESPONDING connection TO data(ls_info).
*    DATA(ls_info) = CORRESPONDING ts_info( connection ).
    DATA(ls_info) = VALUE ts_info( carrid = connection-carrid ).             " O (구조체 생성)

    DATA lt_info TYPE tt_info.
    lt_info = VALUE #( ( carrid = 'AA' ) ( carrid = 'AB' ) ).                " O (타입 추론)
    DATA(lt_temp) = VALUE tt_info( ( carrid = 'AA' ) ( carrid = 'AB' ) ).    " O (타입 직접 지정)
    out->write( lt_temp ).
  ENDMETHOD.
```
</br>

#### Case 3 — 내부 테이블 행 직접 변경
- `ASSIGN` 으로 인터널 테이블 행을 필드 심볼에 연결하여 원본을 직접 변경
```abap
ASSIGN connections[ carrid = 'UA' connid = '3516' ]
    TO FIELD-SYMBOL(<fs_info>).
CLEAR <fs_info>.
out->write( connections ).
```

### 1) 필드 심볼(Field Symbol)
- 메모리의 변수, 구조체, 내부테이블 등을 동적으로 참조하여 값을 읽거나 변경
```abap
FIELD-SYMBOLS <필드심볼명> TYPE 타입.

ASSIGN (변수명) TO <필드심볼명>.                     "동적 변수명
ASSIGN COMPONENT 필드명 OF STRUCTURE 구조체 TO <필드심볼명>.      "구조체 필드
ASSIGN COMPONENT 변수 OF STRUCTURE 구조체 TO <필드심볼명>.        "동적 구조체 필드

LOOP AT 내부테이블 ASSIGNING <필드심볼명>.
  ...
ENDLOOP.
```

### 2) 필드 심볼(Field Symbol) - 동적 변수명 ASSIGN
-  문자열에 저장된 변수명을 `ASSIGN ( )` 으로 실제 변수에 연결하여 값을 변경
```abap
FIELD-SYMBOLS <필드심볼명> TYPE any.
DATA(변수명) = '실제변수명'.
ASSIGN (변수명) TO <필드심볼명>.
<필드심볼명> = 값.
UNASSIGN <필드심볼명>.
```
```abap
CLASS zcl_a06_w03 IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
      TYPES: BEGIN OF ts_temp,
               month(2),
               mcount TYPE i,
             END OF ts_temp.
      TYPES tt_temp TYPE TABLE OF ts_temp WITH KEY month.
      DATA lt_temp TYPE tt_temp.
  
      TYPES: BEGIN OF ts_sbook,
               month01 TYPE i,
               month02 TYPE i,
               month03 TYPE i,
               month04 TYPE i,
               month05 TYPE i,
               month06 TYPE i,
               month07 TYPE i,
               month08 TYPE i,
               month09 TYPE i,
               month10 TYPE i,
               month11 TYPE i,
               month12 TYPE i,
             END OF ts_sbook.
      TYPES tt_sbook TYPE TABLE OF ts_sbook.
      DATA lt_sbook TYPE tt_sbook.
  
      lt_temp = VALUE #(
          ( month = '01' mcount = 10 )
          ( month = '02' mcount = 0 )
          ( month = '03' mcount = 101 )
          ( month = '04' mcount = 19 )
          ( month = '05' mcount = 3 )
          ( month = '06' mcount = 7 )
          ( month = '07' mcount = 0 )
          ( month = '08' mcount = 39 )
          ( month = '09' mcount = 777 )
          ( month = '10' mcount = 34 )
          ( month = '11' mcount = 2 )
          ( month = '12' mcount = 111 )
      ).
  
      FIELD-SYMBOLS <f_month> TYPE any.
  
      LOOP AT lt_temp INTO DATA(ls_temp).
          DATA(lv_num) = ls_temp-month.
          DATA(lv_month) = 'LS_SBOOK-MONTH' && lv_num.
          ASSIGN (lv_month) TO <f_month>.
          <f_month> = ls_temp-mcount.
          CLEAR ls_temp.
          UNASSIGN <f_month>.
      ENDLOOP.
    ENDMETHOD.
ENDCLASS.
```

### 3) AT END OF (Control Break)
- 같은 값으로 묶인 데이터가 끝나는 시점(마지막 행)에서 실행되는 Control Break 문법
- `AT END OF <필드>` 가 실행되면 <필드> 뒤에 선언된 필드는 임시로 초기화(문자형은 *, 숫자형은 0)되며, `SUM` 실행 시 숫자형 필드는 그룹 합계로 변경
```abap
AT END OF <필드명>.
  ...
ENDAT.
```
```abap
CLASS zcl_a06_w04 IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
    TYPES: BEGIN OF ts_data,
             month(2),
             mcount TYPE I,
           END OF ts_data,
           tt_data type table of ts_data.
    DATA: lt_data TYPE tt_data,
          lt_sum LIKE lt_data.
    lt_data = value #(
                        ( month = '01' mcount = '10') ( month = '02' mcount = '20') ( month = '03' mcount = '30') ( month = '04' mcount = '40')
                        ( month = '01' mcount = '20') ( month = '02' mcount = '40') ( month = '03' mcount = '30') ( month = '04' mcount = '40')
                    ).
    SORT lt_data BY month.

    LOOP AT lt_data INTO DATA(ls_data).
      AT END OF month.
        SUM.
        APPEND ls_data TO lt_sum.
      ENDAT.
    ENDLOOP.
    out->write(  lt_sum ).
  ENDMETHOD.
ENDCLASS.
```

### 오늘의 목표
#### 1) S/4HANA vs C/4HANA 2가지의 Cloud
- S/4HANA : On-Premise(클래식)와 Cloud 버전이 모두 있음
- C/4HANA : Cloud 기반으로만 제공

#### 2) Define Table vs Transparent Table
- Define Table : Eclipse(ADT)에서 define table로 생성(Cloud 방식) /
- Transparent Table : SE11에서 생성(클래식 방식)

#### 3) Root View vs Projection View - 2개의 View와 Interface View의 차이
- Interface View : DB 테이블의 데이터를 조회하는 기본 View
- Root View : Business Object의 핵심 View로 Behavior를 정의하는 View
- Projection View : Root View를 Fiori/OData에 노출하는 View

#### 4) Projection View vs Metadata Extension
- Projection View : 노출할 필드, Text, Value Help 등을 정의
- Metadata Extension : Fiori UI(LineItem, Facet, Header 등)를 정의

#### 5) Service Definition vs Service Binding
- Service Definition : 외부에 노출할 CDS(Entity)를 정의
- Service Binding : OData(V2/V4) 서비스를 생성하고 Publish

#### 6) V2(OData V2) vs V4(OData V4) - 기본 개념만
- V2 : 기존 OData 버전으로 기본적인 서비스 제공
- V4 : 최신 OData 버전으로 Draft 등 RAP 최신 기능 지원

## 2. EML
### 1) READ
- Behavior Root(루트 엔티티)를 기준으로 RAP Business Object를 조회·생성·수정·삭제하는 ABAP 문법
```abap
" EML1 : 필요한 필드 조회
READ ENTITIES OF <Behavior Root>
  ENTITY <Entity>
  FIELDS ( 필드명... )
  WITH CORRESPONDING #( 내부테이블 )
  RESULT DATA(결과).

" EML2 : 전체 필드 조회
READ ENTITIES OF <Behavior Root>
  ENTITY <Entity>
  ALL FIELDS
  WITH CORRESPONDING #( 내부테이블 )
  RESULT DATA(결과).

" EML3 : 조회 + 오류/메시지
READ ENTITIES OF <Behavior Root>
  ENTITY <Entity>
  ALL FIELDS
  WITH CORRESPONDING #( 내부테이블 MAPPING ... )
  RESULT 결과
  FAILED 실패
  REPORTED 메시지.

" EML4 : 조회 키 테이블을 직접 생성하여 조회
DATA 조회조건 TYPE TABLE FOR READ IMPORT <Behavior Root>.
조회조건 = VALUE #( ( 키필드 = 키값 ) ).

DATA 조회결과 TYPE TABLE FOR READ RESULT <Behavior Root>.
DATA 실패정보 TYPE RESPONSE FOR FAILED <Behavior Root>.

READ ENTITIES OF <Behavior Root>
  ENTITY <Entity>
  ALL FIELDS
  WITH 조회조건
```

```abap
" UPDATE1 : DB Key로 직접 수정
SELECT FROM <DB Table>
  FIELDS *
  WHERE 조건
  INTO TABLE @DATA(<내부테이블>).

MODIFY ENTITIES OF <Behavior Root>
  ENTITY <Entity>
  UPDATE FIELDS ( 수정필드 )
  WITH VALUE #(
    FOR <wa> IN <내부테이블> (
      Key = <wa>-Key
      수정필드 = 값
    )
  )
  FAILED DATA(<실패>)
  REPORTED DATA(<메시지>).

COMMIT ENTITIES.

" UPDATE2 : READ 후 %tky로 수정

SELECT FROM <DB Table>

  WHERE 조건
  INTO TABLE @DATA(<내부테이블>).

MOVE-CORRESPONDING <내부테이블> TO <조회조건>.

  WITH <조회조건>
```

## 5. Side Effect (연관 필드 자동 갱신)
- 특정 필드가 변경되면 관련 Determination을 실행하여 연관 필드를 자동 계산하고 화면을 즉시 갱신하는 기능
```abap
" Behavior Definition Root
determination <메서드명> on modify { field <변경필드>; }
side effects
{
  field <변경필드> affects field <갱신필드>;
}

" Projection Behavior
side effects
{
  field <변경필드> affects field <갱신필드>;
}

" Class
" Implementation
METHOD <메서드명>.
  READ ENTITIES OF <Behavior_Root> IN LOCAL MODE
    ENTITY <Entity>
    FIELDS ( <변경필드> )
    WITH CORRESPONDING #( keys )
    RESULT DATA(<조회결과>).

  LOOP AT <조회결과> ASSIGNING FIELD-SYMBOL(<조회구조>).
    <조회구조>-<갱신필드>
      = <조회구조>-<변경필드> * <계산값>.
  ENDLOOP.

  MODIFY ENTITIES OF <Behavior_Root> IN LOCAL MODE
    ENTITY <Entity>
    UPDATE FIELDS ( <갱신필드> )
    WITH VALUE #(
      FOR <데이터> IN <조회결과> (
        %tky       = <데이터>-%tky
        <갱신필드> = <데이터>-<갱신필드>
      )
    ).
ENDMETHOD.
```
